Method and limits

How the numbers on this site were made, how the examples were made, and what both leave out.

How the proof numbers are made

  1. A set of sections from OpenStax books under CC BY 4.0 is fixed first. The answer key is the MathML, headings and figure descriptions that OpenStax publishes in its web editions.
  2. Each section is printed to a PDF from OpenStax's web page, using this project's own print stylesheet. These are not the publisher's PDFs.
  3. ReadableSTEM converts the PDF. Its output is scored against the answer key.
  4. The run is recorded. make proof replays the recording with no key, no network and no cost, and writes PROOF.md. A continuous integration job checks that the committed file is what the command writes.

Two sets exist. The development set is the sections the tool was built on, so its numbers show that the pipeline and the harness work. The held-out set was chosen and registered before any system ran on it. Only held-out numbers say something about material the tool has not seen. The home page labels which set its figures come from.

The protocol is in proof/PREREGISTRATION.md, and the method in full is in docs/eval.md and docs/proof.md.

How the examples were made

  • Each example is a stored result. This site calls no model when it is built or opened.
  • The OpenStax pages are printed to PDF, converted with readablestem demo build, and the result is stored with the PDF and the HTML. The fixture was converted with readablestem convert. Each page names the provider, the model and the date.
  • The pages and equations shown on each example were chosen to show different kinds of content. They are illustrations. They are not a sample and they are not evidence of how often the tool is right.
  • The review decisions are the ones the tool would ask for. No decision was taken for the stored result, so the output shows the tool's proposals as they came.

From the README:

  • Input is a PDF. Word and PowerPoint files must be exported to PDF first.
  • A model is in the loop, so two runs on the same file can differ. Document images and the text around them go to the model provider.
  • Equations are the hard part. A symbol, sign or relation that differs from the PDF's text layer is sent to review. An error that agrees with the text layer, or a PDF with no usable text layer, can still pass.
  • Scans and handwriting are converted only on request, by a model reading the page's picture, with every converted equation and table left for a person to check and the original page kept (about 6 in 10 equations exactly right on development pages made into scans, about 2 in 3 on nine real papers made into scans; handwriting checked by eye on four pages). Without the request, and for drawings, such pages are kept as images and flagged.
  • Tables are off by default and have been checked on a local benchmark and the sample, not on a broad set of real course PDFs.
  • Figure alt text is short. It does not replace a long description for a complex diagram.
  • The hosted beta is a free beta open to anyone with a Google account, with spend caps, daily limits for new accounts and short retention. This site is not that app.

About this site

  • It is plain HTML and one stylesheet. It has no scripts, no frameworks, no web fonts, no trackers and no outside requests.
  • Every page is checked with axe-core at 1280 and 320 CSS pixels as part of the repository's tests. Automated checks find some problems only. Please tell the author about any barrier you meet.
  • It is built by site/build.py from files in the repository. docs/site.md says how.
