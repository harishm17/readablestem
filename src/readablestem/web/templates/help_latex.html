When a LaTeX upload fails

{% if latex_source %}You can upload a LaTeX file or a zip of a LaTeX project, and the tool reads it from the source instead of from a PDF. When that does not work, the message says why. This page says what each message means and what you can change.{% else %}This server does not take LaTeX files or zips right now. Compile your source to a PDF and upload that. The rest of this page is for when it does.{% endif %}

At a glance

  • Always available: compile the version students should see to a PDF and upload that.
  • A zip: zip the whole project folder, with every file the document reads.
  • Stopped: the tool stops rather than give students raw code or missing text. The message says what to fix.
  • Finished with parts missing: the page lists them under “Not handled in this file”.

What you can upload

  • One file: a .tex file, with no other files. It must be a complete document: a document class and a document body. A .tex file over {{ tex_file_limit }} is refused, and so is a zip whose .tex and other text files add up to over {{ tex_total_limit }}.
  • A zip of the project: up to {{ project_zip }}. Put in the main file and everything it reads: other .tex files, pictures, .bib and .bbl files, and your own .sty and .cls files. Folders inside the zip are fine, to a path of {{ zip_depth }} names at most.
  • Pictures: PNG, JPEG, GIF and PDF. A file with any other extension (EPS, SVG, another zip) makes the whole upload refused.
  • Left out without a word: what a TeX run leaves behind, such as .aux, .log, .toc and .synctex.gz files, and a __MACOSX folder. They still count against the zip's limits.
  • More than one main file: if a zip has several complete documents, the tool tries to pick the one that nothing else includes, using folder depth and usual names such as main and paper. If it cannot, type the file's name in the upload form's “Main file” box and upload again. The box is under “Uploading a LaTeX project zip with more than one main file?” If the name you type is not a complete document, the message is “No main file was found”.
  • Pages: a source counts against your daily pages as one page for every {{ chars_per_page }} characters of .tex text (comments left out), or one for each \includegraphics or tikzpicture, whichever is larger, and at least one. The count is an estimate made at upload, before conversion.
  • A revised version takes a PDF. Upload LaTeX source as a new document.

When the upload is refused

These come back on the upload form, under the file box. Most of them say that nothing was converted and no pages were taken from your daily allowance, and most say to upload the PDF instead.

  • “could not be opened as a zip file”. The zip is damaged or has a password. Zip the project again without a password.
  • “is too big or has too many files”. A project zip may be up to {{ project_zip }}. A folder counts as a file, a file in the zip may be up to {{ zip_member_limit }}, and a member that unpacks to far more than it takes zipped is refused as well. A single .tex file over {{ tex_file_limit }} gets this message too. Remove what the document does not use.
  • “has a file with a path or a link this tool will not open”. The zip holds an absolute path, a drive letter, .., a backslash, a name used twice, a name that is too long or too deep, or a link instead of a file. Zip the project again with plain files only.
  • “has a kind of file this tool does not read”. A file ends in an extension the tool does not take, such as .eps or .svg, or the zip holds another zip. Convert pictures to PNG, JPEG or PDF and zip again.
  • “uses something this tool will not run”. The source has a command that starts a program or writes a file (for example \write18, \openout, \directlua, or a package such as minted or pythontex), or it names a file by an absolute path, a path that goes up with .., a home folder or a web address. Remove it.
  • “No main file was found”. No .tex file has both a document class and a document body. Check the project.
  • “has more than one main file”. Type the name of the one to convert in “Main file” and upload again.
  • “is longer than one conversion takes”. The estimated page count is over the limit for one document, which the message gives. Split the project into parts.
  • “is a Beamer slide deck, which this tool cannot convert from source yet”. Upload the compiled PDF.
  • “uses a document class this tool cannot read from source yet” or “loads a package this tool cannot read yet”. The message names the class or package. See below.
  • “LaTeX source is not available on this server right now”. Compile it to a PDF and upload that.

When the conversion stops

These appear on the document's page. The tool stops rather than finish with raw commands or missing text where students would see them, and it keeps nothing partial. The pages counted at upload stay counted. The next step is to change the source and upload it again, or to upload the PDF.

  • “asks for the file ... and it is not in the upload”. The source reads a file the zip does not hold. The message gives its name and the line, or lists several. Zip the whole project folder with those files in it.
  • “LaTeX cannot read this source past ...”. A brace or an environment is not closed, so everything after that point would be missing. The message gives the file and line. Compile the source yourself, fix the error and upload again.
  • “has the character ... in its text”. A ^, _, & or # sits in running text, where LaTeX cannot read it. Put an exponent or a subscript inside $ signs, and write the character itself with a backslash: \&, \#, \_ or \^{}.
  • “are not defined”. The source uses commands that no one defined. They would show to students as raw code. Define them in the source. A file the source reads with \input counts.
  • “which this tool cannot read yet”. The source uses commands from a package the tool does not read, or loads a package it refuses by name. If the package is your own file in the zip, the tool does not read package files from the upload: copy the definitions you use into the source. If it is a standard TeX package, upload the PDF.
  • “uses the document class ..., which this tool cannot read from source yet”. Upload the PDF.
  • “could not be converted. Upload the PDF instead.” The source could not be converted and the tool cannot say more. Upload the PDF.
  • “uses something this tool will not run”. The source has a command the tool will not run, as in the list above. Remove it, or upload the PDF.
  • “The server is busy right now”. Upload it again in a few minutes, or upload the PDF.
  • “Reading source files is not available on this server at the moment”. Save the file as a PDF and upload that.

A list under the message names each file or command that stopped it, with the file and line when LaTeX gave them.

Classes and packages it does not read

  • Refused by name: {% if refused_classes %}the {{ refused_classes }} class{% endif %}{% if refused_classes and refused_packages %} and {% endif %}{% if refused_packages %}the {{ refused_packages }} package{% endif %}. The message says to compile the version students should see to a PDF and upload that. An exam source, read without the class's own rules, would show its solutions and correct-answer marks.
  • Read as an article: classes without their own reader (scrartcl, scrreprt, scrbook, memoir and extarticle). Their commands set the layout, not the content.
  • babel: loading it is fine. A document that uses its commands, such as \selectlanguage or \foreignlanguage, stops with “which this tool cannot read yet”.
  • Any other class or package: it is passed to the converter. If errors follow, the job stops and names what it could not read. The tool reads the literal \documentclass and \usepackage lines. One written through a macro is not caught at upload.

When it finishes but a part is wrong or missing

The tool does not stop for these. It asks you, or it says what is missing. Open the document and see the review help for how the decisions work.

  • A formula with an unknown command. It is shown as it was written and becomes a decision: “A formula in the LaTeX source uses a command LaTeX does not know, so it is shown as it was written and is a decision for you.” Correct the LaTeX, or accept it as it is, or choose Leave as written: students then see the LaTeX as it was written, marked “Not converted”.
  • A figure with no picture. The tool could not read a picture from the project: a drawing made in LaTeX, a missing file, or a format it does not read, such as EPS or SVG. You describe it yourself. A figure whose picture is a PNG, JPEG, GIF or PDF in the zip is described like one from a PDF.
  • A picture in a table cell. The picture follows the table as a figure of its own, and the cell reads as empty. The table becomes a decision: say in the cell what the picture is, or accept the table as it is.
  • A formula shown as LaTeX code in a table, heading or caption. The item becomes a decision: correct it, or accept it as it is.
  • Parts it could not read. The document's page says “This tool could not read part of the LaTeX source”, with the words and pictures that are not in the file, listed under “Not handled in this file”. The document is “Partly converted”, not “Ready to share”. Check that the file reads well without them before you share it, or upload the PDF.

When the PDF is the better way

If the source cannot be read, the PDF you compile from it always can be uploaded. The tool then works out headings, lists, tables and equations from how the page looks, which it does less well than reading them from the source. See the known limits for what it does with a PDF.
