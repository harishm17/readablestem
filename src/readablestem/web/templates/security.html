Sign-in and who can see a document

  • People sign in with {{ sign_in_words or "Google" }}{% if microsoft_login %} (Microsoft is for a school or work account from a university that is set up){% endif %}. Students never sign in.
  • A document belongs to the person who uploaded it. Others get the same “not found” page as for a document that does not exist. The owner can share a document with named people, who must sign in with the exact address entered.
  • Every form is protected against cross-site requests, sign-in attempts and uploads are rate limited, and the pages send security headers.

How uploaded files are handled

  • A file is opened first by a separate short-lived process with time and memory limits, and the conversion runs in a child process that can be stopped, with limits on memory, processor time and run time. Page, size and daily limits apply.
  • Everything that reaches a web page is escaped or checked against an allowed list, and the converted file is served with a policy that blocks scripts.
    • {% if latex_source %}
  • LaTeX source is read by LaTeXML in a sandbox with no network.
    • {% endif %}
  • Some steps write a temporary copy of derived content to a private folder on the server, which is removed when the step ends. The uploaded file itself is kept in the database, not on disk.
  • A crafted PDF can still make a conversion worse. The review screen is how a person catches that; it is not a security control.

What has and has not been tested

  • Tested by the project's own checks: who may open which document, the retention clock, that no document content reaches logs, how hostile files are refused, and the escaping of what reaches a page. The application was reviewed against a written checklist before launch.
  • Not done: no independent security test has been made, and no accessibility conformance report is published. The output has not been tested by listening with NVDA, JAWS or VoiceOver.
  • The accepted risks for the beta are listed in the security notes.

No agreement is offered

ReadableSTEM does not sign a school-official agreement or a data processing agreement. There is no company behind it that could sign one. If your institution requires one for any tool that handles course material, ReadableSTEM does not meet that yet. The terms forbid uploading student records, and the tool does not ask for students' names or accounts. More for offices.

Report a problem

Report privately, not in a public issue. Use GitHub's private reporting{% if contact_email %} or email {{ contact_email }} with “ReadableSTEM security” in the subject{% endif %}.
